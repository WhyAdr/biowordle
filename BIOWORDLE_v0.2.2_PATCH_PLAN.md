# BioWordle v0.2.2 patch plan for Gemini

**Base:** `2a0797e06ac53a75f9ac0e7a1a3c385336d5b50e`. Work from [the independent audit](BIOWORDLE_v0.2.1_AUDIT.md). Each phase below has a release check. Keep Chemle and Learn playable through their existing routes, keep the offline standalone, and preserve v1 cumulative totals. Fix scientific copy and source assignments independently of the decision to change answer identities.

## 1. Install portable browser CI and strengthen the rebuild check (F5, F8)

1. Add a private npm manifest and lockfile with an exact `@playwright/test` dev dependency compatible with the supported CI Node release. Use Playwright's pinned Chromium and a small dependency-free Node HTTP server bound to loopback. Serve the app and standalone under one test origin and use fresh browser contexts for isolation. Keep one standalone `file://` smoke for the advertised offline path. Provide npm scripts for Chromium installation and the browser suite. [Playwright CI](https://playwright.dev/docs/ci), [browser installation](https://playwright.dev/docs/browsers), [webServer configuration](https://playwright.dev/docs/test-webserver).
2. Port all five flows and the standalone smoke into named tests. Use locators with retrying assertions and Playwright Clock. Set a deterministic instant and exercise two UTC paths separately. Advance across midnight with the interval paused or deliberately unrun during the stale click, then advance the interval in a separate timer case. Test under a non-UTC browser timezone. Specify Learn targets through controlled RNG or a test fixture. Compute expected counts with independent fixtures that distinguish each visible channel. Use known UTC fixtures or assert the date/key transition directly, including an adjacent-date fixture whose target repeats. [Playwright Clock](https://playwright.dev/docs/clock).
3. In the existing Ubuntu push/PR workflow, run the browser step on checked-out assets before regeneration, or in a separate job that never overwrites them. Add an unconditional tracked-output diff after the Python build. Canonicalize serialization or line endings if byte comparisons expose a host difference, and document the exact scope of any normalization. Upload failure artifacts under the test result path with a short retention period.

Illustrative step sequence for the browser job after checkout and the Node setup step:

```yaml
- run: npm ci
- run: npx playwright install --with-deps chromium
- run: npm run test:e2e
- uses: actions/upload-artifact@v4
  if: failure()
  with:
    name: chromium-failures
    path: |
      playwright-report/
      test-results/
```

**Acceptance tests**

- All original E2E scenarios pass. Exercise both games' automatic clue thresholds one guess before and exactly at unlock, including Chemle scaffold and the different Seqle level-1 threshold.

Cover keyboard navigation and commit for Chemle's combobox. No fixed sleeps, retries based on random targets, or requirement that days with different keys have different answers.
- Break a browser assertion locally or in a test branch and confirm its trace and screenshot upload. Confirm HTTP entry points and a cold `file://` standalone load work without runtime errors or external asset requests for the offline build.
- On a clean matching environment, rebuilding produces no diff in `data/puzzles.json`, `data/puzzles_data.js`, `tests/golden_feedback.json` and `dist/biowordle_standalone.html`. Editing only the tracked standalone inline script causes the release-artifact check to fail. Update README with the new commands, current per-game thresholds, Chemle Learn packs, and Seqle Learn eligibility.

## 3. Calibrate Ranked Seqle against legal probes (F1, F7)

1. First separate `answers` and `probes` in the solver. Use catalog-only simulations for the historical benchmark, then include legal noncatalog probes with a deterministic seed, sample size, sorted alphabet, and an independent or adversarial holdout sample. Score at least greedy entropy and two-step success probability. Match both player-visible feedback and unlock rules, including all clues available after a non-winning guess. Implement bounded or sampled search as needed for CI. Report the search method and label a sampled strategy as a bound.
2. Measure expected survivors and singleton coverage **inside** every opening group after the best first probe. Include the achieved opening group and probe size, counts by number of guesses, unsolved count, mean for solves, median, p95, max, mode-specific cap and fraction solved by it. Report the whole-pool diagnostic under its existing semantics separately from conditioned metrics. For diagnostics that include misses, give misses their own bucket and avoid interpreting a cap as a solved guess count. Keep `≤6` as a Ranked comparison; show Learn `≤8` separately.
3. Prototype three independently validated target set sizes, starting at 60, 90 and 120, with multiple confirmed windows for families where enough evidence exists. Keep positional tiles as the primary experiment. Compare opening charge vs charge after guess 2, and re-run old vs new with identical probe policies and with progressively unlocked context. Partition by family for reporting, include a fixed holdout probe sample, and inspect slow/failed and early-solved targets to distinguish informative clues from overspecific labels. Keep substantially similar spellings distinguishable by actual player-visible feedback. Avoid treating unreviewed pattern matches as biological instances.
4. Recommended initial promotion criteria for the deeper mode, subject to pilot results: greedy catalog and fixed legal-probe benchmark each have a median ≥3, mean ≥2.6, ≤2-guess solves ≤45%, and ≥98% solved within six. Disclose any misses and what fallback clue or redesign addresses them. These are proposed pilot criteria, not measured thresholds. Review the same two-step objective and conditioned opening-group results so a new equilibrium is not set by choice of one weak strategy. Ask an instructor or test players to blind-play examples from the middle and tail of the benchmark before making claims about human difficulty. Ship the correctness and portability work if the expansion fails its criteria. In that case retain the current balance as an explicit known limitation and carry the deeper-mode experiment forward.

Compare representative notebook/harness outputs with the browser-visible observations.

## 4. Make stats and schedule upgrades safe (F2, F6)

1. Persist ranked win records idempotently by game and UTC date and derive totals and the shared streak from those records plus a migration baseline, or use an equivalent transaction-backed storage method. Integrate persistence through the normal win/reveal path for both games. Preserve v2 totals and recorded streak dates on first migration, and the one-time v1-to-v2 behavior. Account explicitly for Learn and classroom wins so they increment the appropriate totals without advancing the daily streak. Use an origin-shared transaction if totals or snapshots require read/modify/write. Subscribe to shared changes for display refresh. Re-reading localStorage before rewriting a whole blob handles sequential stale tabs, while still permitting concurrent lost updates.
2. Make the terminal result durable with the session's win credit, or use deterministic reconciliation on boot so an interrupted write neither loses nor duplicates credit. Define the conflict policy for competing input in the same puzzle. Preserve a completed session against older writes, and use a current snapshot or reject stale conflicting moves rather than combining incompatible guess orders.
3. Treat schedule identity as a per-game version of the canonical ordered Ranked answer roster and chooser semantics. Keep separate dataset/rules identity. Preserve the old schedule for unchanged scopes, including Learn-only changes and metadata edits. Handle actual changes through an explicit cutover date or versioned daily/seed URLs, with archived old results or pinned old classroom answers where appropriate. Read an explicit known legacy key such as `919ad8afb190` only after validating the old payload and its target. Make an incompatible prior daily result visible or archivable. Never re-score old guesses against a different target or silently relabel an old seed's target. Fix the README migration claim if full legacy seed continuity is out of scope.
